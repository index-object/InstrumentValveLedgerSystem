# 仪表阀门台账管理系统 — 权限管理系统设计文档

**版本**: 1.0  
**日期**: 2026-03-22  
**状态**: 初稿

---

## 1. 概述

实现基于角色 + 资源所有权的细粒度权限模型，覆盖台账合集、阀门、维护记录、附件照片的全操作权限。

## 2. 角色定义

| 角色 | 标签 | 定位 |
|------|------|------|
| 员工 | employee | 台账数据录入者，只能管理自己创建的资源 |
| 班长 | leader | 审批者，可查看全部数据但不能编辑 |
| 管理员 | admin | 系统运维，拥有全部权限 |

## 3. 权限模型

### 核心原则

- **后端权限检查不依赖 URL 参数**，始终基于：用户角色、资源所有权（`created_by`）、资源状态
- URL 参数 `from` 仅用于前端 UI 显示控制
- 权限检查函数统一放在 `app/routes/valves/permissions.py`

### 台账合集权限

| 操作 | 员工(自己的) | 员工(他人) | 班长 | 管理员 |
|------|-------------|-----------|------|--------|
| 创建合集 | ✅ | — | ❌ | ✅ |
| 编辑合集 | ✅ | ❌ | ❌ | ✅ |
| 删除合集 | ✅ | ❌ | ❌ | ✅ |

### 阀门权限（按状态）

| 操作 | 员工(自己的草稿/已批/驳回) | 员工(待审批) | 班长(待审批) | 管理员 |
|------|--------------------------|-------------|-------------|--------|
| 编辑 | ✅ | ❌ | ❌ | ✅ |
| 提交审批 | ✅(草稿) | — | — | ✅ |
| 审批/驳回 | ❌ | ❌ | ✅ | ✅ |

### 维护记录权限

| 操作 | 员工(自己的) | 员工(他人的) | 班长 | 管理员 |
|------|------------|------------|------|--------|
| 新增 | ✅ | ✅ | ❌ | ✅ |
| 编辑 | ✅ | ❌ | ❌ | ✅ |
| 删除 | ✅ | ❌ | ❌ | ✅ |

## 4. 访问上下文

| 上下文 | 说明 | 可见范围 |
|--------|------|----------|
| 我的台账 (mine) | 用户自己的合集 | 全部状态（含草稿/待审批） |
| 全部台账 (all) | 系统中所有已审批合集 | 仅已审批 | 
| 审批中心 (approvals) | 待审批项集中处理 | 待审批/已审批/已驳回 |

## 5. 权限检查函数接口

```python
can_create_ledger()      → bool
can_edit_ledger(ledger)  → bool
can_delete_ledger(ledger) → bool
can_create_valve(ledger) → bool
can_edit_valve(valve)    → bool
can_delete_valve(valve)  → bool
can_approve_valve(valve) → bool
can_view_ledger(ledger)  → bool
can_import_data(ledger)  → bool
can_export_data()        → bool
can_create_maintenance() → bool
can_edit_maintenance(record) → bool
can_delete_maintenance(record) → bool
```

## 6. 实施要点

- 后端每个写操作路由增加权限检查
- 模板中注入 `is_owner`、`from_param` 等变量控制 UI 按钮显隐
- 所有角色均可导出数据
- 员工在"全部台账"上下文下自动只读
