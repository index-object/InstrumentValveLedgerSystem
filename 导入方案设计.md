# 仪表台账导入规则系统设计方案

## 一、数据结构总览

动力班（5个文件）和化工班（17个文件）共 22 个台账文件，均遵循统一范式：

```
文件（代表一个中心/装置） → 多个 Sheet（每个 Sheet 代表一种仪表类型明细）
```

每个文件还包含一个**汇总表**（`汇总` / `仪表等级划分汇总表`），按装置列出各类仪表按 A/B/C 等级的数量。

### 仪表类型体系

| 大类 | 子类 | 明细 Sheet 典型名称 |
|------|------|-------------------|
| **压力** | 就地/远传 | 就地压力表、远传压力、压力、就地压力 |
| **温度** | 就地/远传 | 就地温度、温度、远传温度、就地温度计 |
| **流量** | 就地/远传 | 流量计、远传流量计、就地流量、就地流量计 |
| **液位** | 就地/远传 | 液位计、物位计、远传液位计、就地液位、就地液位计 |
| **阀门** | 调节型/开关型 | 调节阀、开关阀、切断阀 |
| **开关** | — | 开关 |
| **特殊仪表** | — | 特殊仪表、机组仪表、电磁阀 |
| **其他** | — | 分析仪、可燃有毒气体检测、电动执行器 |

## 二、核心挑战

| 挑战 | 举例 |
|------|------|
| **Sheet 名不一致** | "就地压力" vs "就地压力表" vs "压力" |
| **列名不一致** | "设备等级" vs "设备分级" vs "仪表等级" vs "设备等级（A/B/C）" vs "设备级" |
| **列数不一致** | 温度 Sheet 少则 14 列，多则 30+ 列 |
| **标题行结构不一致** | 单行标题 vs 双行标题（合并单元格） |
| **合并单元格** | "工艺条件" 下再拆 "介质名称 / 设计温度 / 阀前压力" |
| **序号格式** | 整数（1）vs 浮点数（1.0）|
| **关联组件行** | 调节阀主行后跟多行附属组件（定位器、过滤减压阀、执行机构），序号为空 |
| **分组方式差异** | 动力班以中心划分，化工班以装置划分 |

## 三、架构设计：三层规则引擎 + 可配置模板

```
┌──────────────────────────────────────────────────────┐
│                     导入入口层                        │
│   源文件 → 识别 Sheet 列表 → 逐个 Sheet 处理          │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────┴───────────────────────────────┐
│                 仪表类型识别层（Classifier）            │
│                                                       │
│  第一优先级：Sheet 名称精确匹配（权重 10）               │
│  第二优先级：关键词 SS 匹配（权重 7）                   │
│  第三优先级：列签名识别（权重 5）                       │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────┴───────────────────────────────┐
│                 列映射适配层（Mapper）                  │
│                                                       │
│  智能列名规范化（同义词表）→ 模板化列映射                 │
│  每个仪表类型预定义映射模板 → 目标数据库表                │
│  自动跳过无关/空列                                    │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────┴───────────────────────────────┐
│               数据提取与写入层                          │
│                                                       │
│  跳过合并标题行 → 过滤附属组件 → 逐行读取 → 类型转换    │
│  → 数据清洗 → 写入对应数据库表                         │
└──────────────────────────────────────────────────────┘
```

### 4.3 标题行智能检测

```python
# 检测逻辑伪代码
def detect_header_rows(sheet):
    """
    返回: (标题行索引, 数据起始行索引)
    """
    for row_idx in range(min(10, sheet.max_row)):
        row_values = sheet[row_idx]
        if "序号" in row_values:
            # 检查下一行是否全部或大部分为空
            next_row = sheet[row_idx + 1]
            if is_mostly_empty(next_row):
                return row_idx, row_idx + 2  # 双标题行，数据从第三行开始
            else:
                return row_idx, row_idx + 1  # 单标题行
    return 0, 1  # 兜底
```

**合并单元格处理**：双标题行中，上层标题（如 "工艺条件"）覆盖多个子列，子列的实际列名合并为 `工艺条件.介质名称` 格式。

### 4.5 关联组件行过滤

调节阀/开关阀 Sheet 中，一行主设备后常跟多行附属组件（无序号行）：

```
R3: ['1', '0211', '0211-TV-10103A', '薄膜调节阀', 'C', ...]       ← 主行（有序号）
R4: ['', '', '', '执行机构', '', ...]                              ← 附属组件（序号空）
R5: ['', '', '', '过滤减压阀', '', ...]                            ← 附属组件
R6: ['', '', '', '电气阀门定位器', '', ...]                        ← 附属组件
```

**处理规则**：序号为空/None 的行标记为附属组件，写入关联表或跳过，不计入主表数量。

## 六、关键技术决策

| 决策项 | 方案 | 理由 |
|--------|------|------|
| **规则存储格式** | YAML/JSON 配置文件 | 无需改代码即可维护列映射 |
| **数量列处理** | 从数据行计数，不从汇总表读数量 | 汇总表可能存在手动维护偏差 |
| **文件读取** | openpyxl (.xlsx) + xlrd (.xls) | 兼容两种格式 |
| **多级标题处理** | 合并为字符串如 "工艺条件.介质名称" | 保留完整语义 |
| **关联组件处理** | 通过"序号为空"识别，写入附属表 | 阀门附件与主表分离 |
| **设备等级字段差异** | 同义词表自动匹配 | 覆盖所有变体 |
| **未知列处理** | 保留到 JSON 扩展字段 | 不丢失数据，支持后续扩展 |
